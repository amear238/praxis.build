## Context

PRAXIS routes trading signals: **TradingView → n8n → NinjaTrader 8 → Rithmic → MFFU.**
NinjaTrader 8 (NT8) is a Windows-only x86 .NET app. For the build-first sim phase it must run on a
**Windows 11 ARM VM in Parallels Desktop, hosted on the Mac Studio** — so NT8 runs under x64
**emulation**. That is unproven and this spike gates all downstream Block 1 delivery work
(decision D-2026-07-09-B). A native x64 Windows PC is a required purchase before Block 5 regardless;
this task only decides whether emulation is *good enough for now*.

**Already done:** Parallels Desktop + Windows 11 ARM are installed on the Mac Studio.

## Where the work runs — one machine, two sides

The Windows guest is **inside Parallels on the Mac Studio**, not a separate box. Split the work by side:

| Side | Runs where | Tasks |
|------|-----------|-------|
| **Guest (Windows 11 ARM)** — primary | Inside the VM | C2 NT8 install/launch/responsiveness, C3 sim feed + chart, C4 in-VM watcher detection |
| **Host (macOS)** | On the Mac Studio | C4 Parallels shared-folder mapping, drop the test `.json`, measure latency |

Claude Code runs natively on ARM Windows; only NT8 itself is x64-emulated. Whoever runs this must be
operating on the Mac Studio (local, or Screen-Share / SSH into it) — the VM is not reachable otherwise.

## Checkpoints

### C2 — NT8 viability (guest)
1. Install NinjaTrader 8 in the Windows 11 ARM VM.
2. Launch it; connect a **free NT sim account** (Sim101 / Playback).
3. Record: launched cleanly? responsive or sluggish under emulation? any errors/crashes?
   UI lag on chart scroll and order-entry ticket?

### C3 — Data + chart (guest)
4. Connect the sim data feed; open an **NQ** chart.
5. Confirm bars stream (live or replay) without stalling.

### C4 — File-drop path + latency (host → guest)
6. Configure a **Parallels shared folder** mapping a Mac source dir (e.g. `~/praxis-signals/`) into the guest.
7. Drop a test `signal.json` on the **Mac side**; confirm it appears in the guest.
8. **Measure Mac-write → guest-visible latency** (take a few samples, report ms/s).
   This proves the eventual NinjaScript FileSystemWatcher drop path is viable.
