# fz6 — B1-f consumer nits: readAttempts leak + entrySignal truncation collision

**Bead:** Praxis_build-fz6 · **Target:** `ninjascript/PraxisSignalConsumer.cs` (built in ct5, commit ed2bc9e) · **Date:** 2026-07-12

Two surgical fixes; no other behavior change. Source-only as before — NT8 compile happens inside the
Win11 VM, so verification here is static reasoning plus a reference-vector check of the hash algorithm.
**T1–T4 (trader-touch, still pending) will now exercise this updated source.**

---

## Defect 1 — `readAttempts` leak on reject (and other terminal paths)

### Before

The per-file read-retry counter was purged in exactly one place — after a successful
`File.ReadAllText`:

```csharp
lock (sync) { readAttempts.Remove(fullPath); }
```

A file that hit the `MaxReadAttempts` cap went to `rejected/` via `RejectFile` → `MoveTo` **without**
its `readAttempts` entry ever being removed. On a long-running strategy every such file leaked one
dictionary entry forever.

### After

Purge is centralized in a named helper and anchored at the single structural chokepoint every
terminal disposition passes through — `MoveTo`:

```csharp
private void MoveTo(string fullPath, string destDir, string signalId)
{
    // EVERY terminal disposition (processed/, processed/duplicates/, rejected/) funnels
    // through this method, so purging here is the single chokepoint that keeps the
    // per-file retry counter from leaking on a long-running strategy (bead fz6).
    PurgeReadAttempts(fullPath);
    try { ... }
}

private void PurgeReadAttempts(string fullPath)
{
    lock (sync) { readAttempts.Remove(fullPath); }
}
```

### Why correct — enumeration of every terminal disposition path

| # | Terminal path | Route | Purge site |
|---|---|---|---|
| 1 | Unreadable after `MaxReadAttempts` (IOException branch in `ProcessFile`) | `RejectFile` → `MoveTo(rejectedDir)` | `MoveTo` head |
| 2 | Malformed JSON (`ParseFlatJson` throws) | `RejectFile` → `MoveTo(rejectedDir)` | `MoveTo` head |
| 3 | Validation failure (`ValidateSignal` returns error) | `RejectFile` → `MoveTo(rejectedDir)` | `MoveTo` head |
| 4 | Duplicate `signal_id` | `MoveTo(duplicatesDir)` direct | `MoveTo` head |
| 5 | Accepted + bracket submitted | `MoveTo(processedDir)` direct | `MoveTo` head |
| 6 | Accepted + submission failed (at-most-once bias) | `MoveTo(rejectedDir)` direct | `MoveTo` head |
| 7 | File already moved/gone when dequeued (duplicate-enqueue race) | early `return` at top of `ProcessFile` | explicit `PurgeReadAttempts` at the early return |

That is all seven ways a file's lifecycle ends in this strategy. `RejectFile`'s only file action is
`MoveTo`, so paths 1–3 cannot bypass the chokepoint. The successful-read purge (`ProcessFile`, right
after `ReadAllText`) is retained — the counter has done its job at that point, and it also covers the
theoretical case of an exception escaping between read and disposition. The purge sits **before**
`MoveTo`'s `try`, so even a failed move (share hiccup) purges; the file then stays visible to the
rescan, gets re-processed as a journal DUPLICATE, and hits `MoveTo`/purge again — idempotent.

Residual (accepted, noted for completeness): a file deleted *externally* mid-retry, with no
subsequent FSW/rescan enqueue for that path, can strand one entry — that requires trader interference
in the drop dir, not a strategy disposition, and path 7 clears it on the next enqueue of that name.

Dedup journal contract (9tl): untouched — journal still keys on full `signal_id`, journal-before-submit
order unchanged.

## Defect 2 — entrySignal 40-char truncation collision

### Before

```csharp
string s = sb.ToString();
return s.Length > 40 ? s.Substring(0, 40) : s;
```

NT8 keys bracket/exit (`SetStopLoss`/`SetProfitTarget` OCO pairing) on the entry-signal name. Two
distinct long `signal_id`s sharing a 40-char prefix produced the **same** name → wrong bracket/exit
pairing.

### After — format spec

```
name = "PRX-" + N(signal_id)
N(id): sanitize (non [A-Za-z0-9_\-.] -> '_'), then
  len <= 40  ->  sanitized verbatim                                  (unchanged from ct5)
  len  > 40  ->  sanitized[0..30] + '~' + fnv1a32_hex8(FULL original id)   (= 40 chars)
```

- **Deterministic across restarts:** pure function of `signal_id`; no per-run counter or state.
- **Collision-resistant:** a collision now requires an identical 31-char prefix **and** an FNV-1a-32
  collision over the full original ids (hash input is pre-sanitization, so sanitize-folding can't
  weaken it). FNV-1a is implemented with .NET 4.8 built-ins only (`uint` arithmetic in an
  `unchecked` block, `Encoding.UTF8`) — no new dependencies, no `System.Security.Cryptography`.
- **Length budget:** worst case `"PRX-"` + 40 = **44 chars**, inside NT8's ~50-char tolerance.
- Short ids (≤40 after sanitize) are byte-for-byte unchanged, so the install runbook's T1–T4 example
  names (`PRX-B1F-T1-0001`) remain exact. The runbook never documents the old 40-char truncation or
  the name format, so per the bead spec it needed **no** edit.
- Algorithm cross-checked against published FNV-1a-32 vectors (`"" -> 811c9dc5`, `"a" -> e40c292c`,
  `"foobar" -> bf9cf968`) via a reference implementation; the C# port is a line-for-line
  transcription of that reference.

### Worked example (two 49-char ids sharing a 44-char prefix)

| signal_id | old name (COLLIDED) | new name |
|---|---|---|
| `PRAXIS-2026-07-12T14:30:00Z-NQ-BUY-breakout-alpha` | `PRX-PRAXIS-2026-07-12T14_30_00Z-NQ-BUY-break` | `PRX-PRAXIS-2026-07-12T14_30_00Z-NQ-~d7d6c0d1` |
| `PRAXIS-2026-07-12T14:30:00Z-NQ-BUY-breakout-bravo` | `PRX-PRAXIS-2026-07-12T14_30_00Z-NQ-BUY-break` | `PRX-PRAXIS-2026-07-12T14_30_00Z-NQ-~ccc77c71` |

Old: identical → NT8 pairing corruption. New: 44 chars each, distinct, human-readable prefix kept.

## Scope / verification notes

- No behavior changed beyond the two fixes; no refactors beyond the `PurgeReadAttempts` helper that
  defect 1's "structurally hard to miss" acceptance requires.
- Language level: additions use only constructs already at or below the file's existing C# level
  (no interpolation, no expression bodies, no `nameof`); `unchecked` and `uint.ToString("x8", ...)`
  are .NET 2.0-era.
- Cannot compile on this macOS host (NT8 in Win11 VM) — auditor re-check is static, then T1–T4
  trader-touch tests in the VM exercise this source.
