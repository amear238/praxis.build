## Design (final, as built)
1. **Auditor contract** (`.claude/agents/praxis-auditor.md`, appended section). The final message ends with three bare lines: `VERDICT: PASS` / `COMMIT-INDEX: REAL|<abs path>` / `COMMIT-DIFF-SHA256: <hash>`. The auditor computes the hash itself, with the canonical command `git diff --cached --no-ext-diff --no-textconv --no-color --text --ignore-submodules=none --no-relative`.
2. **Minter** `.claude/hooks/auditor-mint.sh`, registered on SubagentStop with matcher `^praxis-auditor$`. It re-checks `agent_type` itself, and requires the three lines to be the last three lines, each appearing once. It refuses if the words FAIL*, UNVERIFIABLE or BLOCKED appear anywhere, or if the git toplevel is not ROOT. It recomputes the hash for the named index and requires an exact match on a non-empty diff. It then checks provenance through `audit-provenance.sh`: agent transcript path, meta `agentType=praxis-auditor` and `spawnDepth=1`, and an `Agent` tool_use in the parent session transcript. If everything passes, it writes token `.claude/state/audit-pass-<hash>` (tree, index, minter, agent_id, transcript paths) and the AUDIT_LOG row `<ts> praxis-auditor:<aid> <hash> PASS index=…`. It always exits 0 and logs every decision to `.claude/state/mint-log`.
3. **Gate** `.claude/hooks/gate-commit.sh`. All existing checks are kept: form denials including pathspec-after-`--`, one commit per call, single-session, tree binding, single-use deletion. New for the stack master (agent_type praxis-master, no agent_id):
   - The whole command must be `[GIT_INDEX_FILE=<abs path> ]git commit` followed only by `-m <msg>` pairs. Unquoted characters are allowlisted.
   - The payload `cwd` and the git toplevel must equal ROOT.
   - The effective git hooks dir must match HEAD.
   - Only a praxis-auditor token is accepted; a legacy `audit-approve.sh` token is refused.
   - At commit time it re-runs provenance and checks the hash line in the harness-written transcript: the stub `agentId:` tool_result, plus the hand-back as a `user` record or a `queued_command` attachment.
   - The hash and tree are taken from the named index.
   - On allow, it writes `.claude/state/last-allowed`.

   Non-stack callers keep the legacy route.
4. **Detector** `scripts/commit-tree-verify.sh` (PostToolUse Bash). It compares the new HEAD tree with the tree the gate allowed and prints `COMMIT TREE MISMATCH` (exit 2). It is detection only and cannot undo a commit.
5. **Tripwire** `scripts/mint-guard.sh` (PreToolUse Bash|Write|Edit|NotebookEdit). For any `praxis-*` caller it denies:
   - commands naming the mint scripts or token files;
   - writes to AUDIT_LOG, to the gate's state files, to `.beads/hooks/`, or to `shell-snapshots`.

   Paths are normalised before matching. String obfuscation evades it.
6. `audit-approve.sh` (legacy) now uses the canonical diff command. Its behaviour is otherwise unchanged.

**How the PASS reaches the minter (requirement 4):** through the harness's SubagentStop payload (`last_assistant_message`, `agent_transcript_path`, `transcript_path`). ## Residual risks (what a producer-role adversary can still do)
- **Same-uid forgery (RESIDUAL).** Every actor has Bash as the same user. A worker can fabricate a meta file, a subagent transcript, and matching tool_result and hand-back lines in the live session jsonl, then run the minter under a glob name. The result is a token. The design raises the cost to harness-file forgery; it does not prevent it.
- **Environment tampering (RESIDUAL).** An edited `~/.claude/shell-snapshots/*` can define `git()` (W10 A3). Git aliases and `commit-tree`+`update-ref` evade the matcher (hwk family; W6 A4/A5). Hooks run from the working tree, so a producer that edits the gate or minter changes enforcement live, before any audit.
- **Auditor honesty (RESIDUAL).** An auditor that writes "NOT PASS" or "0/3 pass" and then the three lines still mints (W14 F1). The word filter is a heuristic.
- **Post-allow races (detected, not prevented).** A background job can stage after the allow. commit-tree-verify reports it after the fact, unless it also rewrites `last-allowed`.
- **Token re-copy replay** after `reset --soft` (A11). **DoS** by corrupting a token (A16).
- **Non-stack callers** keep the pre-existing pathspec and flag-cluster gaps (W6 A12). Subagents are still held by no-commit-guard, which hwk evades.
- **Over-blocking.** mint-guard now denies the master any Bash command naming these strings, including `grep -i … AUDIT_LOG.md`. The minter refuses any commit-authorising message containing "fail", including evidence like "0 failed".
- **Interactions, not fixed:** `Praxis_build-hwk` (quoted, alias and commit-tree evasion still evades every Bash hook), `-nvn` (compact.sh staging: if it stages into a temp index after a mint, the gate denies on hash or tree mismatch, which is fail-closed; INFERRED), `-22q` (untouched).
